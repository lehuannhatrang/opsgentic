# 2026-07-07

## Pipeline spec — Phase 1 (declarative graph topology)

Made the LangGraph topology and agent/tool wiring declarative, driven by a single
`config/pipeline.yaml`, so the pipeline structure (nodes, ordering, routing, tool wiring) can
be reshaped without editing orchestration Python. Runtime behavior is unchanged.

- Added subpackage `src/opsgentic/pipeline/`:
  - `spec.py` — typed, validated spec loader (`NodeSpec` / `EdgeSpec` / `PipelineSpec`,
    `parse_spec`, `@lru_cache load_spec`, `PipelineSpecError`). Structural validation covers
    unknown entrypoint/interrupt nodes, dangling static/conditional edge targets, empty
    conditional branches, and node-referenced agents missing an `agents:` entry. Depends only
    on `yaml` + `config` (no graph/registry imports — avoids cycles).
  - `registry.py` — the engine layer: `STEP_REGISTRY` (step name -> node function) and
    `ROUTER_REGISTRY` (router name -> router). `_route_after_validation` moved here from
    `graph/builder.py`.
- Added `config/pipeline.yaml` — the default blueprint reproducing the current topology
  (rca -> resolve_target -> validation -> conditional{action|rca|escalate} -> action);
  baked into the image by the existing `COPY config` (same convention as `config/gitops.yaml`).
- Added `pipeline_config_path` setting to `config.py`.
- `graph/builder.py` — `build_app(checkpointer, spec=None)` now interprets the spec (generic
  node/edge/router wiring, `END` sentinel mapping, spec-sourced `interrupt_before`) instead of
  hard-coded topology. Node functions are passed as bare references so `action_node(state,
  config)` still receives `config`.
- `agent_registry.py` — `AGENT_TOOLS` / `NODE_AGENTS` / `OFF_GRAPH_AGENTS` are now derived from
  the spec (public names/types/values unchanged), so the runtime graph, tool loaders, and the
  console graph view share one source of truth.
- Tests: added `test_pipeline_spec.py`, `test_pipeline_registry.py`, `test_builder_pipeline.py`;
  existing `test_agent_registry.py` and `test_graphview.py` pass unchanged. Full suite 25 passed.
- Verified end-to-end: a hermetic CLI run (canned LLM, MCP/DB disabled, no auto-approve) executes
  RCA -> resolve_target -> validation and stops at `awaiting_approval` (the pre-`action` gate),
  matching pre-refactor behavior.
- Docs: documented the blueprint workflow in `README.md` — a "Editing the pipeline (blueprint)"
  section plus Why/Roadmap bullets.
